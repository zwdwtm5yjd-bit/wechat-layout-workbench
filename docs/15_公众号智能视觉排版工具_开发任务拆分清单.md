# 一、实施总原则

# 1.1 先完成闭环，再扩充素材

第一阶段必须优先打通：

```text
登录
→ 新建或粘贴文章
→ 编辑器展示
→ 应用基础主题
→ 插入基础组件
→ 微信预览
→ 一键复制
→ 保存版本
```

在该闭环没有稳定前，不应优先制作：

- 18套完整主题；
- 280个静态组件；
- 36个SVG模板；
- 微信草稿同步；
- 复杂素材更新中心；
- 多人权限；
- AI推荐。

# 1.2 核心Schema先冻结

以下内容必须先完成并通过测试：

- 文档Schema；
- 节点类型；
- 主题Token；
- 品牌Token；
- 组件Manifest；
- SVG协议；
- API错误码；
- 数据库迁移规范。

这些内容若频繁变化，会导致前后端、渲染器、主题、组件和历史版本同时返工。

# 1.3 编辑器与微信输出双轨开发

每个编辑器节点开发时必须同时完成：

1. 编辑器Node；
2. 编辑器Node View；
3. JSON Schema；
4. 服务端微信Renderer；
5. 安全模式Renderer；
6. 静态模式Renderer；
7. 兼容规则；
8. 单元测试；
9. 视觉样稿。

不得先只做“编辑器看起来正常”，后期再补微信输出。

# 1.4 每个阶段都有可运行版本

每个里程碑必须能：

- 启动；
- 登录；
- 打开页面；
- 使用核心功能；
- 运行测试；
- 通过健康检查；
- 使用种子数据验证。

# 1.5 AI编码任务必须小而明确

单次交给Claude/Codex的任务应满足：

- 目标单一；
- 文件范围明确；
- 有依赖说明；
- 有输入输出；
- 有测试要求；
- 有禁止修改范围；
- 可在一次PR中审查。

不应一次要求：

> 把整个系统全部开发完成。

# 1.6 每个任务必须带验收条件

任何任务完成的判断依据不是：

- “代码写完了”；
- “页面出来了”；
- “大概能用”。

而是：

- 测试通过；
- 指定接口可用；
- 指定页面可操作；
- 失败场景可处理；
- 文档和迁移齐全；
- 不破坏已有功能。

# 三、工作量等级

本清单采用相对工作量，不直接等同于自然日。

| 等级 | 含义 | 单人参考 |
|---|---|---|
| XS | 很小修改 | 0.25至0.5天 |
| S | 单一组件或接口 | 0.5至1.5天 |
| M | 完整小模块 | 2至4天 |
| L | 跨前后端模块 | 5至8天 |
| XL | 核心复杂能力 | 9至15天 |
| XXL | 大型系统能力 | 15天以上 |

工作量默认包含：

- 编码；
- 类型；
- 基础测试；
- 简要文档；
- 本地验证。

不包含大规模视觉素材生产。

# 二十六、开发任务冻结

本文件正式冻结以下实施原则：

1. 项目按V0.1、V0.5、V1.0三阶段推进；
2. V0.1先打通粘贴导入到一键复制闭环；
3. 文档Schema必须最先冻结；
4. Token Resolver必须先于大规模主题生产；
5. SVG协议必须先于模板生产；
6. 微信Renderer必须与编辑器节点同步开发；
7. 所有耗时操作通过Worker和Job执行；
8. Redis不保存唯一业务数据；
9. 所有大型操作必须有快照和回滚；
10. 核心共享文件禁止多个Agent并行修改；
11. 主题和组件可在协议冻结后并行生产；
12. 每个AI编码任务必须有明确文件范围和验收条件；
13. 每个PR原则上对应一个任务；
14. 数据库历史迁移不得重写；
15. OpenAPI是前后端契约；
16. V0.1不做草稿同步；
17. V0.5只做4类基础SVG；
18. V1.0再完成18套主题、280个组件和36个SVG；
19. 首版不做多人协同、AI写作、Kubernetes和自动发布；
20. 后续测试与启动提示词必须以本任务清单为基础。
