`S2-IMPORT-001 Python DOCX Worker`

## 完成内容

- 将无业务逻辑的 Python 占位替换为纯标准库 OOXML 解析器，解析
  `document.xml`、`styles.xml`、`numbering.xml`、relationships、内嵌图片和表格；
- 冻结 `DOCX Intermediate v1` JSON Schema 与 Source Block 字段映射，以顺序、类型和
  内容摘要生成可重试的稳定 ID；Node Worker 作为跨语言消费者再校验版本、
  顺序、摘要、图片出现次数、表格映射和统计一致性；
- 保留标题层级、列表级别与原编号文本、受控行内 marks、安全超链接、图片位置、
  图片替代文本和表格行列；重复图片保留每次出现位置，底层资源按内容去重；
- 拒绝 ZIP 路径穿越、绝对/反斜杠路径、重复或加密成员、符号链接、超限文件数/
  解压体积/压缩比、XML DTD/实体、宏、ActiveX 和 OLE 嵌入对象；
- 资源服务支持 50MB 内的私有 `.docx` 直传、内容摘要校验和原文件保留，
  `POST /api/v1/imports/docx` 事务化创建待导入文章与来源文档并投递权威任务；
- BullMQ Worker 使用无 shell 子进程、2 分钟超时和 64MB stdout 上限调用 Python，
  验证原 DOCX 摘要、上传内嵌图片与中间 JSON，并生成受锁定的 Document Schema V1、
  Source Blocks、文章资源引用、状态历史和审计记录；
- 开发与生产 Worker 镜像都包含 Python 3 运行时和解析器源码；新增不启动真实依赖的
  OpenAPI 离线生成器，前端类型已包含 DOCX 上传与导入契约。
