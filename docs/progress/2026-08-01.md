## 今日任务

`S1-JOB-001 BullMQ 任务中心`

## 完成内容

- 新增 `@wechat-layout/job-runtime` 共享运行库，统一 12 个规范队列名、任务/事件契约、
  Redis 连接解析、任务存储、BullMQ 队列协调和 Worker 执行协议；
- 复用既有 `operations.jobs` 与 `operations.job_events` Schema，将 PostgreSQL 作为任务状态、
  进度、错误、结果摘要和事件流的权威来源，Redis / BullMQ 只负责调度与运行时协调；
- 创建任务和首个 `queued` 事件在同一数据库事务内提交；幂等键按 Owner 做 SHA-256 作用域
  隔离，同一用户重复请求返回原任务，不同用户可以安全复用同一外部幂等键；
- BullMQ 任务使用固定 Job ID、指数退避与抖动、持久保留成功/失败记录；自动重试期间数据库
  状态为 `retry_pending`，耗尽次数后保留可手动重试语义；
- 可重试错误和永久错误携带稳定结构化标记，永久错误转为 BullMQ `UnrecoverableError`，不再
  依赖跨构建入口可能失效的 `instanceof`；
- Worker 从占位进程升级为真实维护队列消费者，支持进度、自动重试、永久失败、取消检查和
  安全退出；维护探针用于运行栈与发布验收，不伪造其他尚未实现的业务处理器；
- Worker 每 5 秒写入 15 秒 TTL 心跳；API 就绪检查新增 Worker 探针，Redis 重启后会自动恢复；
- 实现 Owner 隔离的任务列表、详情、取消、手动重试和 SSE 事件接口；写接口继续受 Session、
  CSRF 和 UUIDv7 校验保护；
- 取消操作先事务化写入 PostgreSQL，再移除排队任务或通过 Redis Pub/Sub 调用运行中 Worker
  的 `cancelJob`；终态任务重复取消保持幂等；
- SSE 从 PostgreSQL 事件表回放，不依赖易失 Pub/Sub；`Last-Event-ID` 使用数据库内原始微秒
  时间戳子查询比较，避免 JavaScript `Date` 毫秒精度截断造成游标事件重复；
- 新增单元、HTTP 合约、Testcontainers 和 Docker 烟雾测试，覆盖幂等、Owner 隔离、进度、
  SSE 断线续传、自动/手动重试、永久错误、排队/运行中取消及 Redis 重启；
- Docker 烟测新增任务中心全链路和 Worker 心跳断言，并在有状态服务重启后等待 API / Worker
  就绪恢复；
- 更新 README 与 V0.1 发布检查清单，关闭 `S1-JOB-001` 发布门禁。

## 技术决策

- 不新增任务表迁移：既有 `operations.jobs` 和 `operations.job_events` 已完整满足任务卡字段、
  索引和约束，运行库直接复用并补齐事务语义；
- PostgreSQL 始终是业务事实源；即使 Redis 队列暂时不可用，任务失败原因和事件也会落库，
  Redis 重启不影响历史查询和 SSE 回放；
- 任务取消采用数据库先行，避免 BullMQ 已停止而业务状态仍显示运行中；运行中中断使用
  AbortSignal，并由处理器在阶段边界主动检查；
- 当前只注册可验证的 `maintenance.probe` 处理器。正式渲染仍沿用 `S1-COPY-001` 已交付的同步
  事务协议；后续业务任务可注入 `JobService.enqueue`，无需改变查询、事件和取消协议；
- SSE 使用短轮询数据库而不是把 Redis QueueEvents 当唯一来源，换取重启可恢复性和严格的
  Owner 权限边界；后续可增加通知唤醒优化，但不能移除数据库回放。

## 发现并修复的问题

- 永久错误最初通过 `instanceof` 分类；集成测试从源码与构建产物两个入口加载同一错误类时，
  实测被误判并重试 5 次。改为稳定的 `code + retryable` 结构标记后，永久错误只执行一次；
- SSE 游标最初将 PostgreSQL 微秒时间戳转换为 JavaScript `Date` 后再比较，完整回归捕获到同一
  毫秒内游标事件被重复回放。改为数据库内标量子查询后，游标事件不再重复；
- 本机 pnpm 离线缓存不完整，恢复依赖时需要联网重建 `node_modules`；Vite 间接 WASM 绑定仍有
  既有可选 Peer 警告，不影响安装、测试或构建；
- Docker 经典构建器首次重建镜像重新下载 711 个包，耗时较长，但最终镜像、服务健康和完整
  烟雾测试均通过。
