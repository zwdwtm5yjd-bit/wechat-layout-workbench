## 技术决策

- Manifest 是编辑器和微信 Renderer 的共同事实源，但不携带可执行 Renderer；内置代码
  通过受控 Key 选择，远程包也不能向应用注入脚本；
- 组件实例一旦插入就固化精确版本；未指定版本只在新插入时解析最新可用版本，历史文章
  不自动升级；
- 兼容等级在 Manifest 中沿用 safe、compatible、conditional、risky 四级，映射到现有
  Document Schema 时将 compatible 归入 safe、risky 归入 static，不修改冻结的 V1
  文档兼容枚举；
- Slot 通过 `editorBinding` 映射到 `semanticCard` 的 eyebrow、title、footer 或 content；
  内容 Slot 使用子区块 `semanticRole` 保存 Slot ID，避免新增任意 attrs 或破坏 Document
  Schema V1；
- 收藏只冻结 `{ available: false, value: false }` 接口，不越界增加用户偏好表或持久化；
- 注册中心不提供删除已发布版本，只允许启用或停用，以满足历史文章可重现和安全占位要求。

## 发现问题

- 规范同时存在 `cmp_{category}_{semantic}_{variant}_{number}` 和
  `component_inspection_result` 两种示例；校验器兼容 `cmp_` 正式格式和 `component_`
  旧格式，但拒绝无命名空间的组件 ID；
- Manifest 兼容等级与 Document Schema V1 的兼容枚举并不完全相同；通过显式映射保持
  两侧类型稳定，未为本任务修改 Schema 版本；
- 编辑器普通 `tsconfig.json` 已包含 DOM 类型，但发布构建使用独立

  漂移，新增锁文件内容仅为两个 workspace 依赖；
