# 一、设计目标

主题系统是本项目的核心壁垒之一。

本系统不以“单个标题样式数量”作为主要能力，而以：

```text
完整主题
+ 成套组件
+ 专业语义
+ 多公众号品牌适配
+ 微信兼容
+ 可持续升级
```

作为设计系统核心。

本文件解决以下问题：

1. 一套主题由哪些内容组成；
2. 主题如何作用于文章；
3. 公众号品牌如何覆盖主题；
4. 组件如何分类、命名和版本化；
5. 专业党政、巡察、法律和科技组件如何设计；
6. 主题之间如何混搭；
7. 如何避免素材库越来越杂；
8. 如何保证更新后的旧文章仍可稳定显示；
9. 如何评价一套主题是否达到上线标准；
10. 第一版18套主题具体应设计成什么样。

# 二、核心设计原则

# 2.1 主题优先于单个素材

用户默认流程应当是：

```text
选择完整主题
→ 自动完成全文基础排版
→ 必要时替换局部组件
```

而不是：

```text
逐个选择标题
→ 逐个选择引用
→ 逐个选择卡片
→ 逐个选择分割线
```

# 2.2 语义与视觉分离

例如：

- “整改成效”是语义；
- “红色左线卡片”是视觉；
- “现代政务红”是主题。

同一个“整改成效”组件，应能在不同主题中呈现不同视觉。

# 2.3 公众号品牌高于主题默认色

主题提供视觉风格，公众号提供品牌识别。

优先级：

```text
系统安全默认值
< 主题Token
< 公众号品牌Token
< 文章级设置
< 组件局部覆盖
```

# 2.4 微信兼容高于视觉效果

任何设计若不能稳定复制到公众号，必须：

- 调整结构；
- 降级；
- 提供静态替代；
- 或标记为高风险组件。

# 2.5 精选优于数量

首版280个组件应当做到：

- 风格明确；
- 成套；
- 可复用；
- 手机阅读舒适；
- 与专业内容匹配；
- 不以换色和微调重复凑数。

# 2.6 正式内容不等于老旧

党政、巡察和法律主题必须：

- 庄重；
- 清晰；
- 克制；
- 现代；
- 具有编辑设计感。

不得简单采用：

- 大面积红金；
- 厚重边框；
- 复杂党徽纹样；
- 过多渐变；
- 满屏装饰；
- 老式宣传栏视觉。

# 三、主题系统总体模型

# 3.1 主题层级

主题分为三层：

## A. 主题家族 Theme Family

代表总体设计方向。

例如：

- 现代政务；
- 巡察纪实；
- 律所专业；
- 科技评测；
- 日系编辑。

## B. 主题 Theme

具体完整套系。

例如：

- `government-modern-red`；
- `inspection-documentary-gray`；
- `lawfirm-black-gold`。

## C. 主题配色 Theme Palette

同一主题的颜色变体。

例如：

- 红色版；
- 藏蓝版；
- 墨绿版；
- 黑金版；
- 米色版。

# 3.2 主题包组成

每个主题包至少包含：

# 四、主题设计Token

# 4.1 Token分类

主题Token分为：

1. 色彩；
2. 字体排印；
3. 间距；
4. 圆角；
5. 边框；
6. 阴影；
7. 图片；
8. 动效；
9. 组件；
10. 微信兼容。

# 4.2 色彩Token

```json
{
  "colors": {
    "primary": "#B42318",
    "primaryLight": "#FDECEC",
    "primaryDark": "#7A1712",
    "secondary": "#344054",
    "accent": "#C9A227",
    "textPrimary": "#1D2939",
    "textSecondary": "#667085",
    "textMuted": "#98A2B3",
    "background": "#FFFFFF",
    "surface": "#F9FAFB",
    "surfaceStrong": "#F2F4F7",
    "border": "#EAECF0",
    "borderStrong": "#D0D5DD",
    "success": "#157F3D",
    "warning": "#B54708",
    "danger": "#B42318"
  }
}
```

要求：

- 正文颜色与背景对比度必须满足基本可读性；
- 不允许只使用浅灰正文；
- 党政红不得大面积铺满正文；
- 强调色最多2种；
- 一篇文章主色、辅助色和强调色总数建议不超过4种。

# 4.3 字体排印Token

由于微信公众号字体兼容限制，系统不依赖特殊字体。

```json
{
  "typography": {
    "fontFamilyWechat": "-apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', sans-serif",
    "bodySize": 16,
    "bodyLineHeight": 1.8,
    "bodyLetterSpacing": 0.3,
    "bodyWeight": 400,
    "captionSize": 13,
    "captionLineHeight": 1.6,
    "heading1Size": 22,
    "heading1LineHeight": 1.45,
    "heading1Weight": 700,
    "heading2Size": 19,
    "heading2LineHeight": 1.5,
    "heading2Weight": 700,
    "heading3Size": 17,
    "heading3LineHeight": 1.55,
    "heading3Weight": 600,
    "quoteSize": 16,
    "dataSize": 28
  }
}
```

建议范围：

| 项目 | 建议范围 |
|---|---|
| 正文字号 | 15至17px |
| 正文行距 | 1.7至2.0 |
| 一级标题 | 20至24px |
| 二级标题 | 18至21px |
| 三级标题 | 16至18px |
| 图注 | 12至14px |
| 数据大字 | 24至40px |

# 4.4 间距Token

```json
{
  "spacing": {
    "xs": 4,
    "sm": 8,
    "md": 12,
    "lg": 16,
    "xl": 24,
    "xxl": 32,
    "section": 36,
    "paragraphGap": 16,
    "headingTop": 28,
    "headingBottom": 14,
    "contentPadding": 16
  }
}
```

# 4.5 圆角Token

```json
{
  "radius": {
    "none": 0,
    "sm": 4,
    "md": 8,
    "lg": 12,
    "xl": 18,
    "pill": 999
  }
}
```

正式主题默认：

- 0至8px；
- 不使用过度圆润卡片；
- 不使用大量胶囊标签。

生活、科技主题可使用：

- 8至18px；
- 局部卡片化；
- 但正文主体仍保持清晰。

# 4.6 边框Token

```json
{
  "border": {
    "thin": "1px solid",
    "medium": "2px solid",
    "strong": "3px solid",
    "leftAccent": "4px solid"
  }
}
```

# 4.7 阴影Token

微信长文中阴影应克制。

```json
{
  "shadow": {
    "none": "none",
    "soft": "0 4px 16px rgba(16,24,40,0.06)",
    "medium": "0 6px 20px rgba(16,24,40,0.10)"
  }
}
```

限制：

- 正式主题默认不使用或只使用轻阴影；
- 同屏阴影组件不超过2个；
- 微信安全模式可移除阴影。

# 4.8 图片Token

```json
{
  "image": {
    "defaultRadius": 8,
    "defaultMarginTop": 16,
    "defaultMarginBottom": 16,
    "captionAlign": "center",
    "captionColor": "{colors.textMuted}",
    "captionSize": 13,
    "border": "none",
    "shadow": "none"
  }
}
```

# 4.9 动效Token

仅用于SVG和工具界面，不用于普通静态HTML动画。

```json
{
  "motion": {
    "durationFast": 180,
    "durationNormal": 320,
    "durationSlow": 500,
    "easingStandard": "ease-out",
    "easingEmphasized": "cubic-bezier(0.2,0.8,0.2,1)"
  }
}
```

# 五、公众号品牌Token

# 5.1 品牌Token字段

```json
{
  "brand": {
    "primaryColor": "#9E1B1B",
    "secondaryColor": "#1F3A5F",
    "accentColor": "#C8A45D",
    "textColor": "#1F2937",
    "logoResourceId": "res_logo_001",
    "avatarResourceId": "res_avatar_001",
    "qrCodeResourceId": "res_qr_001",
    "authorName": "公众号作者",
    "copyrightText": "未经授权不得转载",
    "defaultFooterId": "footer_001",
    "defaultCoverId": "cover_001"
  }
}
```

# 5.2 品牌覆盖规则

允许覆盖：

- 主题主色；
- 主题辅助色；
- 主题强调色；
- Logo；
- 二维码；
- 作者；
- 文末；
- 封面；
- 图片水印。

不建议覆盖：

- 主题基础间距；
- 组件结构；
- 正文字号体系；
- 容器嵌套；
- 微信兼容参数。

# 5.3 品牌适配模式

## 强品牌模式

品牌色替换主题全部主色。

适合：

- 律所；
- 企业；
- 个人媒体品牌。

## 柔和品牌模式

仅在：

- 标题；
- 分割线；
- 二维码；
- 文末；
- 标签；

使用品牌色。

适合：

- 党政；
- 巡察；
- 法律专业长文。

## 仅标识模式

只替换Logo、二维码和文末。

适合：

- 强视觉主题；
- 杂志主题；
- 节日主题。

# 六、主题应用机制

# 6.1 应用范围

主题可应用于：

- 全文；
- 当前章节；
- 选中区块；
- 仅标题；
- 仅图片；
- 仅文末。

# 6.2 应用行为

主题应用时：

1. 替换全局Token；
2. 重新映射`styleRef`；
3. 调整组件变体；
4. 应用公众号品牌Token；
5. 检查局部覆盖；
6. 检查不兼容组件；
7. 生成预览；
8. 用户确认后保存。

# 6.3 不得修改

- 原文字；
- 段落顺序；
- 图片内容；
- 法律条文；
- 公文序号；
- 用户锁定区块；
- SVG内容逻辑。

# 七、主题混搭规范

# 7.1 混搭级别

## 安全混搭

同一主题家族内混搭。

例如：

- 现代政务红标题；
- 数据政务卡片；
- 公文极简正文。

## 可接受混搭

设计语言相近。

例如：

- 律所蓝灰；
- 研究报告；
- 商务咨询。

## 高风险混搭

设计语言明显冲突。

例如：

- 清廉新中式标题；
- 科技霓虹卡片；
- 拼贴Zine文末。

# 7.2 风格冲突检测维度

系统检测：

- 主色冲突；
- 字重冲突；
- 圆角冲突；
- 边框冲突；
- 阴影冲突；
- 装饰密度；
- 正式程度；
- 字体风格；
- 图片处理风格；
- 组件年代感。

# 7.3 混搭提示

示例：

> 当前标题使用新中式风格，正文卡片使用科技霓虹风格，整体视觉一致性较低。建议替换为研究报告或政务数据卡片。

系统只提示，不强制阻止。

# 八、组件体系

# 8.1 组件层级

```text
组件分类
→ 组件
→ 组件变体
→ 配色变体
→ 状态
```

例如：

```text
标题
→ 一级标题
→ 左线型
→ 红色版
→ 默认状态
```

# 8.2 组件分类编码

| 分类 | 编码 |
|---|---|
| 首屏 | HERO |
| 导语 | INTRO |
| 标题 | HEAD |
| 正文 | BODY |
| 引用 | QUOTE |
| 提示 | NOTICE |
| 数据 | DATA |
| 卡片 | CARD |
| 列表 | LIST |
| 步骤 | STEP |
| 时间轴 | TIME |
| 图片 | IMAGE |
| 图组 | GALLERY |
| 分割线 | DIVIDER |
| 法律 | LEGAL |
| 党政纪检 | GOV |
| AI科技 | TECH |
| 人物 | PERSON |
| 文末 | FOOTER |
| 二维码 | QR |
| SVG互动 | SVG |

# 8.3 组件ID命名

格式：

```text
cmp_{category}_{semantic}_{variant}_{number}
```

示例：

```text
cmp_head_level1_leftbar_001
cmp_gov_rectification_result_card_001
cmp_legal_issue_border_002
cmp_tech_compare_bento_001
cmp_footer_qrcode_minimal_001
```

# 8.4 组件版本

采用语义化版本：

```text
主版本.次版本.修订版本
```

例如：

```text
1.0.0
1.1.0
1.1.1
2.0.0
```

规则：

- 修订：样式微调、兼容修复；
- 次版本：新增变体、参数；
- 主版本：结构或Schema变化。

# 九、组件基础规范

每个组件必须定义：

- 组件ID；
- 名称；
- 分类；
- 语义角色；
- 适用场景；
- 支持主题；
- Slot；
- 可调属性；
- 默认Token；
- 微信渲染器；
- 编辑器渲染器；
- 兼容等级；
- 静态降级；
- 版本；
- 预览图；
- 使用说明。

# 9.1 Slot规范

通用Slot：

- `eyebrow`：小标签；
- `title`：标题；
- `subtitle`：副标题；
- `body`：正文；
- `meta`：元信息；
- `icon`：图标；
- `image`：图片；
- `footer`：尾部说明；
- `action`：操作提示。

Slot必须定义：

- 是否必填；
- 字数建议；
- 是否允许富文本；
- 是否允许图片；
- 是否受原文锁定；
- 微信导出方式。

# 十、基础组件规范

# 10.1 首屏组件 HERO

至少支持：

- 纯文字首屏；
- 大图首屏；
- 杂志首屏；
- 数据首屏；
- 纪实首屏；
- 新中式首屏；
- 活动首屏；
- 科技首屏。

首屏必须包含：

- 标题；
- 可选副标题；
- 可选日期；
- 可选栏目；
- 可选图片；
- 可选Logo。

不得：

- 标题过小；
- 文字压在复杂背景上无对比；
- 使用过多装饰；
- 首屏高度过长影响正文进入。

# 10.2 标题组件 HEAD

一级标题要求：

- 视觉识别最强；
- 与正文拉开明显层级；
- 不超过两种主要装饰；
- 支持长标题自动换行；
- 长标题换行后不变形。

二级标题要求：

- 比一级标题弱；
- 保持主题语言；
- 不使用大面积色块。

三级标题要求：

- 轻量；
- 可直接融入正文；
- 不使用复杂装饰。

# 10.3 引用组件 QUOTE

变体：

- 左线；
- 引号；
- 背景卡片；
- 重点结论；
- 人物引语；
- 文件原文；
- 法律条文。

要求：

- 引用与正文区别清楚；
- 不得影响长段阅读；
- 可显示来源；
- 正式文章优先左线和浅底。

# 10.4 数据组件 DATA

变体：

- 单数据；
- 双数据；
- 三数据；
- 指标卡；
- 排名；
- 对比；
- 进度；
- 时间数据。

要求：

- 数据为视觉中心；
- 单位清晰；
- 不用装饰替代信息；
- 小屏不溢出；
- 多列可安全降级。

# 10.5 提示组件 NOTICE

语义：

- 提醒；
- 注意；
- 重点；
- 风险；
- 建议；
- 结论；
- 警示。

颜色语义：

- 蓝：信息；
- 绿：完成；
- 黄：提醒；
- 红：风险；
- 灰：补充。

不得只靠颜色区分，必须配合文字或图标。

# 10.6 图片组件 IMAGE

支持：

- 全宽；
- 居中；
- 圆角；
- 边框；
- 纪实；
- 杂志留白；
- 带图注；
- 带编号；
- 前后对比。

# 10.7 文末组件 FOOTER

包括：

- 作者；
- 来源；
- 版权；
- 二维码；
- 关注引导；
- 相关阅读；
- 品牌口号；
- 联系方式。

文末必须支持公众号自动替换。

# 十一、党政纪检与巡察组件规范

首版不少于40个。

# 11.1 工作部署组件

Slot：

- 标签；

# 十七、组件设计尺寸与阅读规范

# 17.1 内容宽度

组件应适应公众号正文宽度。

原则：

- 不写死超出正文的固定宽度；
- 使用百分比；
- 图片最大宽度100%；
- 多列组件必须有小屏降级。

# 17.2 内边距

建议：

- 普通卡片：12至18px；
- 重点卡片：16至22px；
- 小标签：4至8px。

# 17.3 文字行长

正文单行中文字符不宜过密。

组件内长段文字：

- 不使用过小字号；
- 不使用过窄列；
- 不使用左右多列长文。

# 17.4 装饰密度

同一屏幕内：

- 强装饰组件不超过1个；
- 普通卡片不超过2至3个；
- SVG提示不超过1个主操作；
- 标题装饰不与背景装饰叠加过多。

# 二十、素材更新与淘汰机制

# 20.1 主题状态

- Draft：设计中；
- Review：审核中；
- Published：已发布；
- Recommended：推荐；
- Classic：经典；
- Deprecated：停止推荐；
- Archived：归档。

# 20.2 组件状态

同上。

# 20.3 淘汰原则

以下组件进入停止推荐：

- 审美明显过时；
- 微信兼容性下降；
- 与其他组件高度重复；
- 阅读体验差；
- 使用率长期极低；
- 无法适配品牌Token；
- 不符合当前设计规范。

# 20.4 历史兼容

停止推荐不等于删除。

历史文章仍保留：

- 原组件版本；
- 原渲染器；
- 原主题Token；
- 静态降级。

→ 选择升级

# 三十一、技术决策冻结

本文件正式冻结以下规则：

1. 主题采用“家族—主题—配色”三级结构；
2. 每套主题必须是完整套系，不是零散素材；
3. 主题通过Token作用于文档；
4. 公众号品牌Token高于主题色；
5. 主题与原文内容严格分离；
6. 专业组件采用“语义＋Slot＋视觉变体”；
7. 组件ID和版本必须统一规范；
8. 不允许任意CSS进入组件数据；
9. 混搭允许，但必须进行风格冲突提示；
10. 首版包含18套完整主题；
11. 首版重点建设党政纪检、巡察、法律和科技专业组件；
12. 组件必须标记微信兼容等级；
13. 主题和组件更新不得覆盖历史版本；
14. 过时素材停止推荐但不删除；
15. 所有主题必须通过长文、手机、品牌和微信兼容测试；
16. 首版默认主题为“高级极简”；
17. 第一批先开发6套主题验证设计系统；
18. 后续主题生产严格按统一测试样稿验收。
