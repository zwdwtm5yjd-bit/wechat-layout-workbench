# 一、信息架构设计目标

本系统的信息架构必须服务于以下产品目标：

1. 让用户快速进入排版，不被复杂后台功能干扰；
2. 让文章、主题、组件、公众号和素材之间关系清晰；
3. 让“快速排版”和“精细设计”在同一编辑器内顺畅切换；
4. 让SVG互动不成为单独的高门槛工具；
5. 让多公众号品牌切换成为系统级能力；
6. 让素材更新、版本管理和兼容检查可以长期扩展；
7. 让第一版可控，同时为后续多用户、商业化和多平台发布预留结构。

---

# 二、总体信息架构

系统一级信息架构分为八个核心模块：

```text
工作台
├── 文章
├── 排版编辑器
├── 主题中心
├── 组件中心
├── SVG互动
├── 公众号
├── 素材更新
└── 系统设置
```

其中：

- **工作台**：负责快速开始和最近工作；
- **文章**：负责文章项目、版本、状态和归档；
- **排版编辑器**：负责实际排版与设计；
- **主题中心**：负责完整主题套系；
- **组件中心**：负责静态组件、专业组件和个人组件；
- **SVG互动**：负责互动模板、向导和专业编辑；
- **公众号**：负责多公众号品牌档案和同步设置；
- **素材更新**：负责远程主题、组件和兼容补丁；
- **系统设置**：负责账号、安全、存储、备份和偏好。

# 三、全局导航结构

## 3.1 桌面端主导航

建议采用左侧固定导航栏，默认宽度72至88像素，展开后宽度220至240像素。

一级入口：

1. 工作台；
2. 文章；
3. 主题；
4. 组件；
5. SVG互动；
6. 公众号；
7. 素材更新；
8. 设置。

底部固定入口：

- 当前账号；
- 云端保存状态；
- 帮助与反馈；
- 系统版本。

## 3.2 顶部全局栏

除编辑器外，大多数页面顶部显示：

- 当前页面标题；
- 全局搜索；
- 新建排版；
- 导入文章；
- 通知；
- 账号菜单。

编辑器页面顶部使用独立的编辑器工具栏，不显示普通全局栏。

## 3.3 全局快捷入口

支持以下快捷动作：

- `Command + K`：全局命令面板；
- `Command + N`：新建排版；
- `Command + O`：导入Word/WPS；
- `Command + P`：打开预览；
- `Command + S`：手动保存；
- `Command + Shift + C`：兼容检查；
- `Command + Shift + P`：一键复制；
- `Command + Shift + B`：切换公众号；
- `Command + Z`：撤销；
- `Command + Shift + Z`：重做。

# 五、登录页

# 5.1 页面目标

为个人私有云端系统提供简单、安全的访问入口。

# 5.2 页面内容

- 产品Logo；
- 产品名称；
- 账号输入；
- 密码输入；
- 记住设备；
- 登录按钮；
- 忘记密码；
- 登录异常提示；
- 当前系统版本。

# 5.3 第一版范围

第一版仅支持：

- 单用户账号；
- 密码登录；
- 登录设备记录；
- 可选双因素认证；
- 登录失败次数限制。

暂不支持：

- 公开注册；
- 第三方账号登录；
- 团队邀请；
- 多组织切换。

# 六、工作台首页

用户登录后，应在十秒内开始排版，不需要先进入复杂管理页面。

采用Bento卡片布局，桌面端分为四个区域。

## A. 快速开始区

- 粘贴文章；
- 导入网页；
- 从历史文章复制；
- 从主题新建。

## B. 最近文章区

显示最近6至10篇文章：

- 标题；
- 目标公众号；
- 使用主题；
- 最后编辑时间；
- 当前状态；
- 兼容评分；

## C. 公众号区

显示多个公众号卡片：

- 头像；
- 名称；
- 品牌主色；
- 最近文章数；
- 默认主题；
- 授权状态；
- 快速切换。

## D. 素材更新区

显示：

- 最新主题；
- 新增组件；
- SVG更新；
- 微信兼容补丁；
- 节日专题包；
- 安装状态。

# 6.3 首页辅助模块

- 最近使用组件；
- 我的收藏；
- 本周排版数量；
- 当前云端存储占用；
- 自动备份状态；
- 版本更新提示。

# 八、新建与导入流程

# 8.1 新建入口

所有新建入口最终进入统一导入向导。

# 8.2 导入向导步骤

```text
步骤1：选择导入方式
步骤2：选择目标公众号
步骤3：上传或粘贴内容
步骤4：选择格式清理方式
步骤5：结构识别预览
步骤6：选择排版强度
步骤7：选择推荐主题
步骤8：进入编辑器
```

# 8.3 导入方式页面

提供四张主要卡片：

- Word/WPS；
- 复制粘贴；
- 网页文章；
- 空白排版。

每张卡片显示：

- 适用场景；
- 支持格式；
- 处理方式；
- 预计结果。

# 8.4 格式清理页面

提供三个选项：

1. 保留结构并清理样式；
2. 完全清理格式；
3. 尽量保留原样。

默认选中第一项。

同时显示清理预览：

- 将删除哪些格式；
- 将保留哪些结构；
- 图片数量；
- 表格数量；
- 标题数量；
- 可能存在的问题。

# 8.5 结构识别页面

左右对照：

- 左侧：原始内容；
- 右侧：识别后的段落角色。

用户可修改：

- 主标题；
- 副标题；
- 一级标题；
- 二级标题；
- 正文；
- 引用；
- 法条；
- 案例；
- 数据；
- 图注；
- 结语。

确认后进入主题选择。

# 8.6 推荐主题页面

同一篇文章同时生成3至6个首屏预览。

每个方案显示：

- 主题名称；
- 适用类型；
- 配色；
- 排版强度；
- 兼容等级；
- 是否含SVG建议；
- 应用按钮。

支持“对比模式”，最多同时对比4套。

# 二十八、信息架构设计原则总结

本系统的信息架构坚持以下原则：

1. **排版优先**：用户登录后最快一步进入编辑；
2. **方案优先**：先选择完整主题，再调整局部组件；
3. **上下文优先**：右侧属性只显示当前对象设置；
4. **内容与素材分离**：文章不依赖某一主题永久绑定；
5. **公众号与品牌绑定**：公众号切换即品牌切换；
6. **SVG场景化**：从用途进入，而不是从技术进入；
7. **更新可控**：新素材安装不覆盖旧版本；
8. **微信兼容可见**：任何重要操作都能看到兼容等级；
9. **普通模式简单**：隐藏专业参数；
10. **专业模式可扩展**：为后续高级设计保留能力。

# 三十一、信息架构冻结结论

本文件确认以下结构：

1. 系统采用左侧一级导航；
2. 编辑器采用独立三栏布局；
3. 工作台作为登录后的默认首页；
4. 文章、主题、组件、SVG和公众号分别管理；
5. 快速排版与精细设计共用同一编辑器；
6. SVG互动既有模板中心，也有向导和专业编辑器；
7. 多公众号通过品牌档案管理；
8. 兼容检查和预览是发布前必经能力；
9. 素材更新独立成一级模块；
10. 第一版桌面端完整、移动端以预览为主；
11. 第一版保留单用户体验，但数据结构预留多角色；
12. 所有后续页面原型和开发拆分均以本架构为准。
