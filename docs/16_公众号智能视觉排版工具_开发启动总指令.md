# 二、项目基本信息

## 项目名称

公众号智能视觉排版工具

当前仅为工作名称，开发阶段不因产品正式命名未确定而停止。

## 项目目标

开发一款支持多公众号品牌、现代主题、自由模块编辑、SVG互动、微信预览、一键复制及后续草稿同步的云端智能视觉排版工具。

## 使用场景

用户已经完成文章写作，通过以下方式导入：

- Word/WPS；
- 复制粘贴；
- 网页导入；
- 空白文章。

系统负责：

- 清理原格式；
- 识别文章结构；
- 应用主题；
- 插入视觉组件；
- 生成SVG互动；
- 应用公众号品牌；
- 微信兼容检查；
- 一键复制；
- 后续同步草稿箱。

## 目标用户

V0.1至V1.0阶段：

```text
个人私有使用
```

不按公共SaaS、多租户和大规模商业系统设计首版。

## 核心功能

- 文章导入；
- 视觉排版；
- 原文锁定；
- 主题系统；
- 组件系统；
- SVG互动；
- 多公众号品牌；
- 微信预览；
- 微信兼容检查；
- 一键复制；
- 历史版本；
- 后续草稿同步。

## 非核心功能

首版不开发：

- AI写作；
- AI改写；
- AI润色；
- AI标题生成；
- AI摘要生成；
- 多人实时协同；
- 自动群发；
- 自动发布；
- 原生移动App；
- Kubernetes；
- 插件市场；
- 收费系统；
- 多租户SaaS。

## 前端展示

需要。

## 数据库

需要。

## 权限系统

首版仅Owner实际使用，但数据库和接口预留：

- owner；
- editor；
- publisher；
- viewer。

## 预期复杂度

高。

## 后续扩展

可扩展，但当前必须先完成V0.1闭环。

# 三、技术决策冻结

以下技术路线已经冻结，开发时不得随意替换。

## 3.1 工程架构

```text
模块化单体
+ 独立异步Worker
+ 独立Scheduler
```

不采用首版微服务。

## 3.2 Monorepo

```text
pnpm Workspace
+ Turborepo
```

## 3.3 前端

```text
Next.js
React
TypeScript
Tiptap
ProseMirror
TanStack Query
Zustand
Tailwind CSS
Radix UI
dnd-kit
```

## 3.4 后端

```text
NestJS
REST API
OpenAPI
Server-Sent Events
```

## 3.5 数据库

```text
PostgreSQL
Drizzle ORM
SQL Migration
```

## 3.6 队列与缓存

```text
Redis
BullMQ
```

Redis不得保存唯一业务数据。

## 3.7 对象存储

开发环境：

```text
MinIO
```

生产环境：

```text
腾讯云COS
```

通过S3兼容适配器访问。

## 3.8 DOCX解析

```text
独立Python Worker
python-docx
lxml
Pillow
```

V0.1不阻塞于完整DOCX解析，先完成粘贴导入。

## 3.9 权威文档格式

```text
Tiptap/ProseMirror JSON
```

微信HTML只是派生输出，不是权威存储。

## 3.10 微信输出

```text
服务端统一Renderer
→ 内联CSS
→ 安全清洗
→ 兼容规则
→ Clipboard API
```

不得直接复制编辑器DOM。

## 3.11 部署

首版：

```text
Docker Compose
```

不使用Kubernetes。

- 多公众号完整品牌；
- SVG互动；
- 微信草稿同步；

# 十八、开发过程决策规则

开发中遇到问题时，按以下顺序处理。

## 18.1 已有文档明确

直接按文档执行。

## 18.2 文档未明确，但不影响核心架构

采用最简单、可回滚的实现，并记录在：

```text
docs/decisions/
```

文件格式：

```text
ADR-0001-决策名称.md
```

## 18.3 影响核心Schema或技术路线

停止该任务，输出：

- 问题；
- 影响；
- 方案A；
- 方案B；
- 推荐；
- 是否阻塞。

不得私自大幅改造。

## 18.4 外部接口变化

例如微信接口变化：

- 先查官方文档；
- 更新连接器；
- 不修改业务核心；
- 记录接口版本；
- 增加兼容测试。
