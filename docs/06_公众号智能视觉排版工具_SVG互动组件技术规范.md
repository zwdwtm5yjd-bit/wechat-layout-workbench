# 一、建设目标

SVG互动是本项目第一版的核心功能，但不能被设计成一个独立、复杂、只有设计师会用的专业工具。

系统需要实现：

```text
低门槛模板
+ 场景化向导
+ 专业参数编辑
+ 微信兼容检查
+ 静态降级
+ 多公众号品牌适配
```

目标用户不需要理解SVG代码，只需要理解：

- 想让用户点击什么；
- 点击后显示什么；
- 是否可以滑动；
- 有几个状态；
- 失败时显示什么静态内容。

本项目不追求制作任意动画，而是建立一套：

> 面向微信公众号、可配置、可测试、可降级、可持续扩展的互动组件协议。

# 二、技术边界

# 2.1 SVG的定位

SVG是一种基于XML的二维矢量图形格式，可包含：

- 矢量图形；
- 栅格图片；
- 文本；
- 分组；
- 裁剪；
- 遮罩；
- 变换；
- 动画；
- 事件触发。

本项目使用SVG的目的不是绘制复杂插画，而是：

- 组织多个视觉状态；
- 响应点击或触摸；
- 切换图层；
- 展开内容；
- 实现滑动或揭晓；
- 在公众号文章中提供轻量互动。

# 2.2 微信兼容边界

微信公众号正文对HTML、CSS、SVG和交互能力存在平台限制，并可能随微信版本、系统和编辑器规则变化。

因此，本项目不把任何第三方平台当前可运行的效果视为永久规则，而采用：

```text
能力白名单
+ 实机测试
+ 兼容配置文件
+ 版本化规则
+ 静态降级
```

系统不得仅依赖浏览器中运行正常，就判断公众号中一定可用。

# 2.3 不使用任意JavaScript

第一版SVG互动不得依赖用户自定义JavaScript。

原因：

- 微信正文环境不适合依赖任意脚本；
- 任意脚本存在XSS风险；
- 不利于兼容检查；
- 不利于组件版本管理；
- 无法保证复制和草稿同步稳定；
- 会使用户上传SVG变成代码执行入口。

第一版互动优先基于：

- SVG结构；
- SVG事件触发；
- SMIL动画；
- 受控链接；
- 受控状态切换模板；
- 系统预生成图层。

# 2.4 不支持的能力

第一版不支持：

- 任意JavaScript；
- `foreignObject`；
- 外部脚本；
- 外部CSS；
- 未审核的远程SVG；
- iframe；
- 任意HTML嵌入；
- 复杂物理动画；
- 依赖传感器的交互；
- 音视频自动播放；
- 用户输入表单；
- 真实数据实时请求；
- 复杂游戏逻辑；
- 任意路径脚本编程。

# 三、SVG互动分层

# 3.1 第一层：模板模式

适合大多数用户。

用户只需要：

- 选择模板；
- 替换图片；
- 填写少量文字；
- 选择提示语；
- 预览；
- 插入文章。

模板模式不得显示：

- 图层树；
- SVG节点；
- 时间轴；
- 事件表达式；
- 原始代码。

# 3.2 第二层：向导模式

适合需要定制互动逻辑的用户。

向导按步骤设置：

1. 内容用途；
2. 状态数量；
3. 触发方式；
4. 图片和文字；
5. 动画方式；
6. 操作提示；
7. 静态降级；
8. 兼容预览。

# 3.3 第三层：专业模式

适合高级用户。

开放：

- 图层；
- 状态；
- 触发区域；
- 动画时间；
- 遮罩；
- 裁剪；
- 图片适配；
- 多设备预览；
- 组件配置JSON；
- 只读SVG结构预览。

仍不开放任意脚本和任意SVG代码执行。


# 4.2 画布Canvas

```json
{
  "width": 750,
  "height": 1000,
  "viewBox": "0 0 750 1000",
  "responsiveMode": "width",
  "backgroundColor": "#FFFFFF",
  "maxHeight": 2400,
  "overflow": "hidden",
  "safeArea": {
    "top": 24,
    "right": 24,
    "bottom": 24,
    "left": 24
  }
}
```

设计基准宽度统一使用750设计单位，实际输出通过`viewBox`和百分比宽度适配。

# 4.3 资源Resource

```json
{
  "resourceKey": "cover",
  "resourceId": "res_001",
  "type": "image",

  "height": 1000,
  "mimeType": "image/jpeg",
  "required": true,
```

- `image`；
- `gif`；
- `icon`；
- `text`；
- `shape`；
- `qr_code`。

# 4.4 图层Layer

```json
{
  "layerId": "layer_cover",
  "type": "image",
  "name": "封面图",
  "resourceKey": "cover",
  "zIndex": 10,
  "visibleInStates": ["state_closed"],

    "scaleX": 1,
    "scaleY": 1,
    "rotate": 0,
    "opacity": 1

  "clickable": true

```

图层类型：

- 图片；
- 文字；
- 形状；
- 遮罩；
- 裁剪；
- 分组；
- 触发区；
- 操作提示；
- 品牌标识。

# 4.5 状态State

```json
{
  "stateId": "state_closed",
  "name": "未展开",
  "initial": true,
  "visibleLayerIds": [
    "layer_cover",
    "layer_hint"
  ],
  "ariaLabel": "点击查看详情"
}
```

状态必须：

- 有唯一ID；
- 指定初始状态；
- 明确可见图层；
- 明确可达路径；
- 不允许无出口死状态。

# 4.6 触发Trigger

```json
{
  "triggerId": "trigger_open",
  "type": "click",
  "targetLayerId": "hit_open",
  "sourceStateId": "state_closed",
  "transitionId": "trans_open",
  "debounceMs": 250,
  "enabled": true
}
```

允许的触发类型：

- `click`；
- `tap`；
- `swipe_left`；
- `swipe_right`；
- `swipe_up`；
- `swipe_down`；
- `auto`；
- `animation_end`；
- `link`。

系统内部可将`click`和`tap`统一处理，但测试中必须覆盖触摸设备。

# 4.7 过渡Transition

```json
{
  "transitionId": "trans_open",

  "toStateId": "state_open",

    "type": "fade_slide",
```

动画类型白名单：

- 无动画；
- 淡入；
- 淡出；
- 左移；
- 右移；
- 上移；
- 下移；
- 缩放；

- 揭幕；

# 五、互动引擎设计

首版以16类互动引擎为基础。

模板数量可以增加，但底层引擎不应重复开发。

# 5.1 点击展开 `click_expand`

## 用途

- 查看详细说明；
- 展开长内容；
- 展开案例；
- 展开名单；
- 展开图片。

## 状态

```text
收起
→ 展开
→ 可选再次收起
```

## 配置

- 展开方向；
- 展开高度；
- 是否可回缩；
- 触发区域；
- 提示文字；
- 展开动画；
- 静态完整图。

## 限制

- 展开后的总高度必须设上限；
- 长内容应优先拆成图片或正文；
- 不能隐藏必须阅读的关键事实；
- 同一文章不宜连续使用多个超长展开。

# 5.2 点击换图 `click_switch`

## 用途

- 前后状态；
- 方案切换；
- 图文解释；
- 产品不同界面；
- 案例结果揭晓。

## 状态

2至6个。

## 配置

- 点击整图或局部；
- 是否循环；
- 状态指示；
- 是否允许返回；
- 切换动画；
- 提示。

# 5.3 连续点击推进 `click_sequence`

## 用途

- 故事推进；
- 步骤展示；
- 逐层揭晓；
- 流程说明；
- 时间节点。

## 限制

- 首版状态不超过8个；
- 必须显示当前进度或明确提示；
- 最后状态必须可返回或结束明确。

# 5.4 左右滑动图集 `horizontal_gallery`

## 用途

- 摄影；
- 活动现场；
- 产品界面；
- 多图对比；
- 人物介绍。

## 配置

- 图片数量；
- 分页提示；
- 是否首尾循环；
- 图片比例；
- 图注；
- 滑动提示。

## 限制

- 首版建议2至10张；
- 重要信息不能只藏在最后一张；
- 静态降级采用纵向图集或拼图。

# 5.5 上下滑动长图 `vertical_scroll`

## 用途

- 时间线；
- 长名单；
- 流程图；
- 证据链；
- 长海报。

## 限制

- 容器高度必须明确；
- 必须有上下滑动提示；
- 长图资源需压缩；
- 静态降级可显示缩略图并在正文补充。

# 5.6 滑动展开 `swipe_reveal`

## 用途

- 揭晓答案；
- 展开主视觉；
- 显示完整图片；
- 活动发布。

## 形式

- 左右开；
- 上下开；
- 单层拉开；
- 双层拉开。

# 5.7 前后对比滑块 `before_after`

## 用途

- 整改前后；
- 修复前后；
- 设计前后；
- 产品界面对比；
- 摄影处理对比。

## 配置

- 前图；
- 后图；
- 初始分割位置；
- 滑块方向；
- 标签；
- 操作提示。

## 静态降级

- 两图并排；
- 上下对比；
- 拼接对比图。

# 5.8 双开门 `double_door`

## 用途

- 活动揭幕；
- 新品发布；
- 重要结论；
- 节日主题；
- 品牌展示。

## 限制

- 使用频率低；
- 不适合正式长文连续使用；
- 党政文章仅用于活动首屏且需克制。

# 5.9 折叠手风琴 `accordion`

## 用途

- 法条；
- 问答；
- 争议焦点；
- 常见问题；
- 多项说明。

## 配置

- 条目数量；
- 单开或多开；
- 默认展开项；
- 标题高度；
- 展开动画；
- 静态全部展开图。

## 限制

- 首版不超过8项；
- 标题必须简短；
- 关键内容应在静态降级中完整存在。

# 5.10 卡片翻转 `card_flip`

## 用途

- 问题与答案；
- 正面与背面；
- 人物与介绍；
- 概念与解释；
- 风险与建议。

## 限制

- 不用于超长文本；
- 正反面文字应简短；
- 必须有翻转提示；
- 静态降级为上下两卡。

# 5.11 时间轴推进 `timeline_progress`

## 用途

- 巡察流程；
- 项目节点；
- 案件过程；
- 版本更新；
- 品牌历程。

## 配置

- 节点数量；
- 横向或纵向；
- 点击或自动；
- 图片；
- 日期；
- 说明。

# 5.12 点击显示文字 `hotspot_annotation`

## 用途

- 图片注释；
- 证据说明；
- 产品功能；
- 地图信息；
- 现场照片说明。

## 配置

- 热点数量；
- 热点位置；
- 提示框位置；
- 点击后是否保持；
- 是否允许多个同时显示。

## 限制

- 点击区域不得过小；
- 重要信息需在降级图中编号说明；
- 不得使用透明到完全不可见的无提示触发区。

# 5.13 点击播放GIF `gif_trigger`

## 用途

- 操作演示；
- 动态流程；
- 产品功能；
- 前后动画。

## 配置

- 静态封面；
- GIF；
- 是否循环；
- 点击后是否可恢复；
- 文件大小提示。

# 5.14 轻量视差 `parallax_story`

## 用途

- 品牌故事；
- 人物专题；
- 旅行和摄影；
- 重点活动长页。

## 限制

- 首版只提供受控模板；
- 不做复杂多轴视差；
- 必须提供减少动态版本；
- 正式文章默认不推荐。

# 5.15 多选分支 `choice_branch`

## 用途

- 小测试；
- 情景选择；
- 知识问答；
- 风险判断；
- 趣味互动。

## 配置

- 题目；
- 选项；
- 结果状态；
- 是否显示答案；
- 是否允许重选。

## 限制

- 不收集用户数据；
- 不进行服务端计分；
- 第一版只做单题或轻量分支；
- 不作为正式调查问卷工具。

# 5.16 点击跳转 `click_link`

## 用途

- 跳转文章；
- 跳转小程序；
- 跳转视频号；
- 跳转报名页；
- 跳转公众号资料。

## 要求

- 链接必须通过白名单与格式校验；
- 编辑器中显示跳转目标；
- 发布前检查失效；
- 不允许隐藏恶意链接；
- 无法跳转时静态内容仍有意义。

# 九、SVG生成管线

```text
互动协议JSON
→ Schema校验
→ 资源校验
→ 品牌Token合并
→ 模板渲染
→ 生成SVG DOM
→ ID去重
→ 安全清洗
→ 微信兼容转换
→ 资源内联或替换
→ 静态降级生成
→ 多设备预览
→ 兼容报告
→ 保存版本
```

# 9.1 ID去重

同一文章可能插入多个SVG。

所有内部ID必须添加实例前缀：

```text
svg_{interactionId}_{localId}
```

避免：

- 遮罩ID冲突；
- 裁剪ID冲突；
- 动画ID冲突；
- 事件目标冲突；
- 渐变ID冲突。

# 9.2 资源处理

图片资源应：

- 从系统对象存储读取；
- 转换为允许的发布资源；
- 记录尺寸；
- 限制文件大小；
- 生成静态备用资源；
- 不直接引用未知第三方地址。

# 9.3 SVG优化

正式输出前：

- 删除编辑器辅助图层；
- 删除无用元数据；
- 合并可合并路径；
- 清理无用定义；
- 压缩空白；
- 保留必要ID；
- 不破坏事件和动画引用。

不能盲目使用通用压缩器，否则可能删除：

- 动画ID；
- `begin`引用；
- 遮罩引用；
- 事件目标；
- 可访问标签。

# 十、安全规范

SVG本质上是可解析的XML标记，可能包含脚本、事件属性、外部资源或其他危险结构，因此所有上传和生成内容必须经过严格清洗。

# 10.1 安全策略

采用纵深防御：

```text
不接受任意代码
+ 标签白名单
+ 属性白名单
+ URL白名单
+ DOM清洗
+ 服务端复检
+ CSP和资源隔离
+ 自动安全测试
```

# 10.2 禁止标签

默认禁止：

- `script`；
- `foreignObject`；
- `iframe`；
- `object`；
- `embed`；
- `audio`；
- `video`；
- 未审核`style`；
- 未知自定义标签；
- 外部文档引用。

# 10.3 禁止属性

默认禁止：

- 所有`on*`事件属性；
- 任意脚本URL；
- `javascript:`；
- 未知协议；
- 外部CSS地址；
- 未审核`href`；
- 未审核`xlink:href`；
- 内嵌事件处理代码。

注意：

> 互动触发不通过用户输入的`onclick`等脚本属性实现，而由系统模板生成受控的SVG动画关系。

# 10.4 允许标签候选

允许列表根据兼容测试动态维护，候选包括：

- `svg`；
- `g`；
- `defs`；
- `rect`；
- `circle`；
- `ellipse`；
- `line`；
- `polyline`；
- `polygon`；
- `path`；
- `image`；
- `text`；
- `tspan`；
- `clipPath`；
- `mask`；
- `linearGradient`；
- `radialGradient`；
- `stop`；
- `animate`；
- `animateTransform`；
- `set`；
- `title`；
- `desc`。

实际微信输出允许列表以实机测试通过的兼容规则文件为准。

# 10.5 清洗器

建议使用：

- DOMPurify作为一层清洗；
- 自定义SVG AST验证器作为第二层；
- 服务端XML解析器作为第三层；
- 模板白名单作为最终限制。

不能仅依赖一个通用清洗库。

# 10.6 外部SVG上传

第一版原则：

- 用户上传的SVG仅作为静态图片处理；
- 不直接作为互动组件执行；
- 可转换为PNG/WebP备用图；
- 需要进入专业组件库时必须人工审核和重新模板化。

## Safe

- 结构简单；
- 无复杂状态；
- 无外链；
- 已通过主流设备测试；

- 有基础互动；

- 复杂互动；
- 必须预览；

## Experimental

- 图片加载失败；
- 重复插入多个SVG。

2. 标记受影响模板；
3. 暂停高风险模板推荐；
4. 通知用户；
5. 提供兼容修复；
6. 不自动修改历史文章；
7. 重新生成静态降级。

# 十二、静态降级规范

# 12.1 所有SVG必须降级

每个互动组件必须生成：

- 完整静态图；
- 或静态多图结构；
- 或正文替代组件。

# 12.2 降级策略

## Replace Whole

整个SVG替换为一张静态图。

适合：

- 双开门；
- 视差；
- 点击切换。

## Stack States

将多个状态纵向排列。

适合：

- 卡片翻转；
- 点击换图；
- 问题答案。

## Grid States

多状态拼图。

适合：

- 图集；
- 产品界面对比；
- 多方案。

## Text Supplement

互动中隐藏的文字同步保留在正文。

适合：

- 法条；
- 案例；
- 风险提示；
- 重要结论。

# 12.3 关键内容原则

以下内容不得只存在于隐藏互动状态：

- 纪法条款；
- 重要事实；
- 风险提示；
- 版权说明；
- 发布主体；
- 核心结论；
- 重要数字；
- 法律免责声明。

# 十三、资源准备规范

# 13.1 图片格式

推荐：

- JPEG：照片；
- PNG：透明图、UI截图；
- WebP：编辑器预览和系统存储；
- GIF：必要的短动画；
- SVG：系统生成的矢量元素。

微信发布时具体格式以兼容测试结果为准。

# 13.2 图片尺寸

设计基准：

- 宽度750px；
- 二倍图可使用1500px宽；
- 长图高度根据模板限制；
- 前后对比图必须同尺寸；
- 翻转卡正反面必须同尺寸；
- 滑动图集建议统一比例。

# 13.3 文件大小

系统应设置建议阈值而非写死永久微信上限。

建议内部控制：

- 单张普通图优化后不超过1.5MB；
- 单个GIF尽量不超过5MB；
- 单个SVG全部资源总量建议不超过8MB；
- 单篇文章SVG资源总量建议不超过30MB。

超出后提示压缩，不直接静默处理导致画质显著下降。

# 13.4 文本

SVG中的长文本不建议直接使用矢量`text`承担正文。

优先：

- 文字转为系统生成图片；
- 或在SVG下方保留正文；
- 或只在SVG中显示短标签。

原因：

- 字体兼容；
- 换行；
- 小屏阅读；
- 微信环境差异；
- 无障碍可读性。

# 十四、操作提示规范

互动组件必须让用户知道可以操作。

# 14.1 提示形式

- 点击图标；
- 手指图标；
- 左右箭头；
- 上下箭头；
- 轻量动效；
- “点击查看”；
- “左右滑动”；
- “向上滑动”；
- “点击翻转”。

# 14.2 提示要求

- 文案短；
- 不遮挡核心内容；
- 与背景对比清楚；
- 首次状态可见；
- 不只依赖动效；
- 支持品牌色；
- 可在操作后隐藏。

# 14.3 正式主题

党政、巡察和法律文章使用：

- 线性图标；
- 小号说明；
- 克制动画；
- 不使用卡通手势。

# 十五、触发区域规范

# 15.1 点击区域

建议最小触发区：

- 不低于44×44视觉像素等效面积；
- 重要操作尽量整卡可点；
- 不使用难以发现的小热点。

# 15.2 热点

热点必须：

- 可见或有编号；
- 在专业模式显示边界；
- 支持位置吸附；
- 防止重叠；
- 显示移动端预览。

# 15.3 滑动

滑动组件必须避免：

- 与微信页面整体滚动冲突；
- 横滑区域过窄；
- 用户不知道可滑动；
- 垂直滑动阻断文章阅读。

# 十六、动画规范

# 16.1 动画时长

建议：

| 动画 | 时长 |
|---|---:|
| 状态切换 | 180至400ms |
| 展开 | 300至600ms |
| 翻转 | 350至600ms |
| 揭幕 | 500至900ms |
| 自动提示 | 800至1600ms |
| 故事推进 | 400至800ms |

# 16.2 动画原则

- 快速响应；
- 不拖延阅读；
- 不连续闪烁；
- 不大幅震动；
- 不默认无限循环；
- 不使用高频闪动；
- 不使用可能引发不适的强烈缩放。

# 16.3 减少动态

系统预览页和编辑器应支持“减少动态”。

公众号正式输出无法保证读取所有用户偏好时，组件仍应：

- 提供静态降级；
- 避免必要信息依赖运动；
- 不使用快速闪烁；
- 不使用长时间自动动画。

# 十七、无障碍与可读性

# 17.1 必须字段

每个SVG组件应包含：

- 可读名称；

- 操作提示；
- 静态替代；
- 图片替代文字；

- 不只用红绿区分；
- 提供文字或图标；
- 保证提示与背景对比；
- 热点不能完全透明且无提示。

# 17.3 文本

- SVG内小字不低于可读标准；
- 长文不塞入互动图；
- 法律和党政内容保留正文文本；
- 互动不能降低信息可检索性。

# 三十三、风险与控制

| 风险 | 控制措施 |
|---|---|
| 微信规则变化 | 兼容规则版本化、实机测试、静态降级 |

# 三十四、技术决策冻结

本文件正式冻结以下规则：

1. 第一版SVG互动必须具备模板、向导和专业三种模式；
2. 所有互动基于统一JSON协议；
3. 首版建设16类互动引擎和36个模板；
4. 模板必须数据驱动，不为每个模板单独开发逻辑；
5. 第一版禁止任意JavaScript和任意远程SVG执行；
6. SVG互动优先使用受控SVG结构和动画机制；
7. 所有SVG必须经过标签、属性、URL和DOM清洗；
8. 用户上传SVG默认按静态资源处理；
9. 每个SVG必须提供静态降级；
10. 关键内容不得只存在于隐藏互动状态；
11. 所有内部ID必须实例化，防止多组件冲突；
12. 兼容规则必须版本化并通过微信实机测试；
13. 党政纪检和巡察内容默认推荐无互动或轻互动；
14. 互动操作必须有清晰提示和足够触发区域；
15. 同一文章的SVG数量和资源体积必须受控；
16. 动画不得高频闪烁、无限干扰或阻碍阅读；
17. 模板更新不得覆盖历史版本；
18. 微信规则变化时优先提供降级和替代模板。
